# Директор 0.4.2-preview — исправление запуска окна

Диагностика 0.4.1 на Android API 36 показала `NullPointerException` в `PhoneWindow.getInsetsController`, вызванный из `LocalActivity.createWorkspace`. Настройка системных панелей выполнялась до создания DecorView; проверка возвращённого контроллера на null не защищала от исключения внутри самого вызова.

В 0.4.2 настройка панелей перенесена после `setContentView`. Общий `WindowChrome` дополнительно создаёт/получает DecorView перед обращением к контроллеру. Обработка отсутствующего контроллера и прежний путь Android 8–10 сохранены. Очередь, разрешения и оформление Glass 04 не менялись.

Проверено без эмулятора:
- 14 новых JVM-проверок: воспроизведение прежнего порядка с null DecorView; исправленный путь для API 30, 35 и 36; уже созданное окно; повторный вызов; null-контроллер; старые API 26 и 29.
- Ещё 224 проверки очереди, хранилища, адаптера и технической диагностики. Итого 238 проверок/сценариев. Android-объекты в JVM-тестах подставные; это не проверка на устройстве.
- Компиляция обоих вариантов, подпись v2/v3, zipalign, целостность ZIP и compiled manifest/DEX.
- В скомпилированном LocalActivity проверен порядок: установка содержимого предшествует WindowChrome.
- Сертификат совпадает с 0.4.1; applicationId `app.hashqueue`, versionCode 7. Новых разрешений нет.

Установка: выключить службу автоочереди, обновить приложение поверх 0.4.1 без удаления и открыть его обычным значком. После успешного открытия снова включить службу. Если появляется экран восстановления, скопировать новый отчёт.

Исправлена обнаруженная ошибка в коде запуска Activity. Успешный запуск именно на realme, подключение службы и полный цикл ChatGPT ещё требуют проверки на телефоне. Эмулятор не запускался.
