# Директор-оркестратор

Публичные выпуски Android-приложения и исходники сайта загрузки.

- Сайт: https://director-orchestr.pages.dev/
- APK 0.4.5-preview: https://github.com/markakula4-stack/director-orchestr-releases/releases/tag/v0.4.5-preview
- [Подключение автопубликации и реальный тест](docs/SETUP_RU.md)

Файлы сайта находятся в `site/`. Проверенный APK хранится в `releases/<tag>/` и публикуется во вложениях GitHub Releases перед обновлением сайта. Основные кнопки скачивают ту же сборку непосредственно с Cloudflare из `site/downloads/`; GitHub сохранён как запасная ссылка. `latest.json.apkUrl` — исходный GitHub-адрес, `downloadUrl` — прямая загрузка с сайта. Исходники Android-приложения в этот репозиторий не загружены. Автоматические архивы Source code на странице выпуска относятся к файлам репозитория, а не к установщику Android.

## Публикация сайта

Сценарий **Deploy site to Cloudflare** запускается при изменении `site/`, `releases/`, `scripts/` или самого сценария в ветке `main`. Его также можно запустить вручную на вкладке Actions. Перед первым запуском нужны два секрета Cloudflare. После их добавления изменение файлов в main запускает реальную публикацию; доступен и ручной запуск.

Сначала отдельное задание проверяет размер и SHA-256 APK, создаёт preview-релиз и загружает файл. Повторный запуск не перезаписывает уже опубликованный APK: содержимое должно совпасть. Только после успешной публикации APK сценарий подтверждает существующий проект `director-orchestr`, использует его фактическую production-ветку и публикует сайт без пересоздания проекта. Проверка после публикации сравнивает живые файлы с коммитом, проверяет старую ссылку скачивания и скачивает APK с обоих адресов с проверкой размера и SHA-256. Для прямой загрузки дополнительно проверяются заголовки файла и HEAD. Запрос HTTP Range проверяет частичный ответ 206 либо полный ответ 200 с точным совпадением байтов; результат отдельно указывается в отчёте. Отсутствие необязательного Content-Length не заменяет и не отменяет проверку фактически скачанного файла.

При выпуске новой версии скопируй подписанный APK также в `site/downloads/` с тем же именем, обнови `downloadUrl` и пять основных кнопок. Проверка сравнивает каждую размещённую копию с исходным APK в `releases/`; незнакомые и отличающиеся APK не публикуются. Старые версии в `site/downloads/` можно сохранять, чтобы ссылки продолжали работать.

Локальная проверка: `node scripts/validate-site.mjs` (Node.js 24).

## Статус приложения

0.4.5-preview исправляет вставку и поиск кнопки отправки, убирает обязательную служебную приписку для новых планов, снижает лишнюю работу панели и удерживает экран при её отображении. Выбор ChatGPT, DeepSeek или Claude, до 20 команд, таймеры, ручной режим и Glass 04 сохраняются.

После обновления выключи «Проверять служебную отметку», выбери пресет 3 / 3 / 0 и сохрани новый план. Старый план намеренно сохраняет прежний протокол, ранее выбранные задержки не сбрасываются. При нулевом интервале следующего шага вставка начинается после подтверждения готового ответа, а до отправки сохраняется 3 секунды.

Обычный режим требует наблюдаемого начала генерации и нового завершённого ответа с действиями ответа. Неясный, слишком быстрый или повторяющийся ответ может потребовать ручной проверки. Вопросы распознаются эвристически. Строгий режим с DONE/WAIT/ERROR доступен отдельно. Неизвестный результат отправки автоматически не повторяется.

Пройдено 553 JVM-проверки и сценария, собраны и проверены оба APK, подпись совпадает с предыдущим выпуском. Эмулятор не использовался. Полный цикл и плавность панели 0.4.5 на физическом Android 16/realme ещё требуют приёмки. Подробности — в заметках выпуска.

APK не имеет сетевого разрешения. Нужны открытое выбранное приложение и разблокированный телефон. Локальная модель и второй изолированный аккаунт в выпуск не входят. Автопубликация сайта не является автообновлением APK на телефоне.
