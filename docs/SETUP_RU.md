# Автопубликация сайта: настройка и реальный тест

Сайт остаётся на **https://director-orchestr.pages.dev/**. Установочные APK публикуются в GitHub Releases; такая же проверенная копия доступна напрямую с Cloudflare. Для обновлений сайта используется этот же публичный репозиторий `markakula4-stack/director-orchestr-releases`.

Код сайта и сценарий **Deploy site to Cloudflare** находятся в этом репозитории. Для первой публикации нужны два секрета Cloudflare. Пока первый запуск не завершился успешно, рабочую автопубликацию считать подтверждённой нельзя. ZIP для обновления сайта загружать не требуется.

Подключению помощника уже предоставлен доступ к этому репозиторию. Если при следующем подключении возникнет отказ записи, проверь **Repository access** в настройках установленного GitHub-приложения и сохрани доступ к существующим проектам.

## 1. Скопируй Account ID Cloudflare

Войди в Cloudflare и выбери аккаунт, в котором находится проект `director-orchestr`.

В разделе **Workers & Pages** найди **Account Details → Account ID** и скопируй значение. Другой способ: поиск в панели Cloudflare → `Copy account ID`.

Нужен Account ID, не Zone ID и не адрес электронной почты.

## 2. Создай токен публикации

Открой раздел **API Tokens** в Cloudflare. Выбери **Create Token → Custom token / Get started**.

| Поле | Значение |
| --- | --- |
| Token name | `director-orchestr-deploy` |
| Permission | `Account → Cloudflare Pages → Edit` |
| Account Resources, если поле показано | `Include → Specific account → аккаунт с director-orchestr` |

Этот токен даёт право изменять Pages-проекты выбранного аккаунта; это не ограничение только одним проектом. Другие разрешения для этого сценария не нужны.

Проверь итоговые права и создай токен. Скопируй его сразу в GitHub Secrets на следующем шаге. Сам токен не отправляй в чат, README, код или скриншот. Для этой настройки не нужен Global API Key.

## 3. Добавь два секрета в GitHub

Открой https://github.com/markakula4-stack/director-orchestr-releases

Перейди **Settings → Secrets and variables → Actions → New repository secret**. Создай две записи по очереди:

| Name | Secret |
| --- | --- |
| `CLOUDFLARE_ACCOUNT_ID` | Account ID из шага 1 |
| `CLOUDFLARE_API_TOKEN` | Новый токен из шага 2 |

Выбирай именно **Repository secrets**, а не Variables и не секреты другого репозитория. Названия скопируй точно, без пробелов. После сохранения в списке будут видны названия; значения секретов GitHub обратно не показывает.

## 4. Выполни первый настоящий запуск

В этом репозитории открой **Actions → Deploy site to Cloudflare → Run workflow**. Выбери ветку **main** и нажми **Run workflow** ещё раз для запуска.

Если GitHub сначала предлагает включить Actions в этом репозитории, включи их, затем открой сценарий. Это запускает публикацию настоящего сайта, а не предпросмотр. Для публикации APK отведено до пяти минут, для публикации и проверки сайта — до десяти минут.

Сценарий:

1. Проверит файлы сайта, ссылки, размер и SHA-256 локального APK. Создаст preview-релиз и загрузит APK; существующий файл при повторном запуске не перезаписывается.
2. Проверит доступ к существующему проекту `director-orchestr`; новый проект он не создаёт.
3. Прочитает настоящую production-ветку проекта из Cloudflare и опубликует сайт в неё.
4. Сверит опубликованные файлы с тем же коммитом GitHub.
5. Проверит старую ссылку, скачает APK с Cloudflare и GitHub с проверкой размера и SHA-256. У прямой загрузки проверит имя файла, тип и HEAD. Отдельно проверит реакцию на HTTP Range: частичный ответ либо полный файл, если сервер проигнорировал диапазон. Во втором случае поддержка докачивания не считается подтверждённой.

Проверка всего запуска должна стать зелёной. Если шаг публикации зелёный, а последняя проверка красная, сайт уже мог обновиться — не считай это отсутствием публикации. При ошибке пришли ссылку на запуск и название упавшего шага; секреты отправлять не нужно.

## 5. Проверь результат на телефоне

Открой https://director-orchestr.pages.dev/ и обнови страницу.

- Нажми **Скачать для Android**. Должен скачиваться `Director-Orchestrator-0.4.2-preview.apk` напрямую с сайта, без перехода на GitHub. Под основной кнопкой есть запасная ссылка GitHub.
- В центре загрузки должна быть ссылка **Версия и файл на GitHub →**. Она открывает опубликованный выпуск `v0.4.2-preview`.
- Размер текущего APK: **62070 байт**. SHA-256: `fec8826fb09ca07ad82a0ac19baae9f81f40017b45e1f65f1a018cda656bffdb`.

Скачивание и установка — разные проверки. Установку на realme проверяем отдельно; изменение места скачивания не устраняет блокировку Play Protect само по себе.

На телефоне отдельно проверь новый светлый интерфейс и короткую автоочередь. Включи доступ через настройки приложения, открой выбранный ChatGPT, нажми «Проверить», затем «Старт». Оставь телефон разблокированным. Если поле или кнопка отправки не найдены, очередь должна остановиться; сохрани диагностику, не перезапускай её многократно.

## 6. Докажи, что следующие обновления идут автоматически

После зелёного первого запуска напиши помощнику: **«Два секрета добавлены, первый запуск зелёный — проверяем обновление без моего участия»**. Можно приложить ссылку на запуск Actions.

Для контрольного изменения помощник внесёт небольшую нужную поправку в текст сайта и сохранит её в `main`. Версия APK при таком тесте не меняется.

Критерий успеха: без ручной загрузки ZIP и без повторного нажатия Run workflow появляется новый запуск с событием **push**, он завершается успешно, а новая подпись видна на сайте по прежнему адресу. APK и его версия при этом не меняются. Так мы отдельно проверим и первый деплой, и автоматическую реакцию на следующий коммит.

Новый APK для следующего выпуска кладётся в `releases/<tag>/` вместе с `NOTES.md`. Поля `site/latest.json` и все пять основных кнопок скачивания обновляются на ту же версию. Тот же подписанный APK копируется в `site/downloads/`. `apkUrl` сохраняет GitHub-адрес, `downloadUrl` указывает прямой Cloudflare-адрес; запасная ссылка ведёт на `apkUrl`. Публикация сайта начнётся только после успешной загрузки APK. Для этого используется встроенный `GITHUB_TOKEN` с правом `contents: write` только в задании `release`; отдельный пользовательский токен не нужен.

## Если запуск остановился

| Сообщение или шаг | Что проверить |
| --- | --- |
| GitHub release request failed: HTTP 403 | Права встроенного GITHUB_TOKEN: задание release должно иметь contents: write |
| Missing / Add repository secret | Оба секрета сохранены в этом репозитории, имена совпадают |
| HTTP 401/403 на проверке Cloudflare | Правильный токен, его срок действия и разрешение Pages Edit |
| HTTP 404 / project not found | Account ID принадлежит аккаунту с существующим проектом director-orchestr |
| The live site still serves a different commit | Публикация могла пройти, но проверка ещё видит другую версию; нужна ссылка на запуск для диагностики |
| APK checksum/size differs | Не продолжать выпуск: данные latest.json и файл APK не совпали |
